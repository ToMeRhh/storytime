# Gemini Provider Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Google Gemini support for bedtime story generation and illustration generation with configurable models via environment variables.

**Architecture:** Reorganize `server/src/llm/` into dedicated `story/` and `image/` sub-domains with explicit interfaces. Implement Gemini providers using `@google/genai` for story text (`gemini-3.8-flash`) and image generation (`gemini-3.1-flash-image`), update config resolution, error handling, and deployment configurations.

**Tech Stack:** Node.js, Express, TypeScript, `@google/genai`, `tsx`, `better-sqlite3`, `supertest`.

**Spec:** [docs/superpowers/specs/2026-09-26-gemini-provider-support-design.md](file:///root/dev/storytime/docs/superpowers/specs/2026-09-26-gemini-provider-support-design.md)

## Global Constraints

- Language & Runtime: TypeScript 5.7+ on Node.js 20.
- Gemini SDK: Use `@google/genai` for both text and image operations.
- Configuration: Controlled purely via server environment variables (`GEMINI_API_KEY`, `LLM_PROVIDER`, `LLM_MODEL`, `IMAGE_PROVIDER`, `IMAGE_MODEL`).
- Defaults:
  - When `LLM_PROVIDER=gemini`: `LLM_MODEL` defaults to `gemini-3.8-flash`.
  - When `IMAGE_PROVIDER=gemini`: `IMAGE_MODEL` defaults to `gemini-3.1-flash-image`.
  - Backward compatibility: Existing defaults (`LLM_PROVIDER=openai`, `IMAGE_PROVIDER=openai`, `gpt-image-1.5`) remain unchanged when not configured.
- Illustration Resilience: Retain 5-step retry ladder (prompt, retry, wholesomeness, de-brand, fallback) and non-blocking asynchronous image delivery.

## Review Focus

1. Missing `GEMINI_API_KEY` when `LLM_PROVIDER=gemini`: Must throw an explicit error `'GEMINI_API_KEY is not set'` before network calls.
2. Missing `GEMINI_API_KEY` when `IMAGE_PROVIDER=gemini`: Image generation must fail gracefully, returning `null` images without breaking the story response.
3. First-line title parsing: Hebrew story generated by Gemini must correctly parse title and body via `splitTitleAndBody()`.
4. Reference photo support: When a room photo exists for a location figure, `geminiImageProvider` must attach the image as an inline base64 part.
5. Parallel execution: All 3 scene illustrations must be requested in parallel via `Promise.all` with `onScene` callbacks updating progress.

```typescript
import { GoogleGenAI } from '@google/genai';
import config from '../../config';
import logger from '../../logger';
import { LLMPrompt } from '../../types';
import { StoryProvider } from './types';

let client: GoogleGenAI | null = null;

export function resetClientForTesting(): void {
  client = null;
}

function getClient(): GoogleGenAI {
  if (!client) {
    if (!config.geminiApiKey) {
      throw new Error('GEMINI_API_KEY is not set');
    }
    client = new GoogleGenAI({ apiKey: config.geminiApiKey });
  }
  return client;
}

export async function generateStory({ system, user, maxTokens }: LLMPrompt): Promise<string> {
  const start = Date.now();
  try {
    const response = await getClient().models.generateContent({
      model: config.llmModel,
      contents: user,
      config: {
        systemInstruction: system,
        maxOutputTokens: maxTokens,
      },
    });

    const text = (response.text || '').trim();
    logger.debug(
      { model: config.llmModel, durationMs: Date.now() - start, usage: response.usageMetadata },
      'gemini generateContent succeeded'
    );
    return text;
  } catch (err) {
    logger.error(
      { err, model: config.llmModel, durationMs: Date.now() - start },
      'gemini generateContent failed'
    );
    throw err;
  }
}
```
